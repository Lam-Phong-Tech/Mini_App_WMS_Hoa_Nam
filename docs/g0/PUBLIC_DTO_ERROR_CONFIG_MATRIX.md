# PUBLIC DTO, ERROR, AND CONFIG MATRIX — G0

## Response envelope

Every public endpoint returns JSON UTF-8 in this six-field envelope. Required fields are always present, including on failure.

| Field | Success | Failure |
| --- | --- | --- |
| `success` | `true` | `false` |
| `message` | Safe user-facing summary | Safe user-facing summary; never raw upstream/stack data |
| `data` | Endpoint DTO | `null` |
| `meta` | Request/version/pagination metadata as applicable | Safe request/retry/maintenance metadata as applicable |
| `error_code` | `null` | Stable machine-readable code |
| `errors` | `null` | Field-to-array mapping for validation; otherwise `null` |

`meta.request_id` is generated by the API; clients may send `X-Request-ID` for correlation but it is not a security credential. Timestamps are ISO-8601 UTC. No envelope may contain secret, stack trace, supplier/internal source, price, inventory quantity, or PII other than an accepted quote request while it is in transit.

### Product and variant rules

- A public product/card/detail/related result is selected only when internal publication is `PUBLISHED` and BE explicitly projects public availability as `IN_STOCK` or `PREORDER`. `PREORDER` is an approved requestable public state; it is not a raw `OUT_OF_STOCK` state and carries no quantity, date, warehouse, or delivery promise.
- Hand Tools use one public product family with available variants. Power Tools may expose Solo/Kit/battery/charger/bundle variants only when approved data exists.
- `primary_code` is optional and is passed through only from an approved real source. The client never generates SKU, barcode, specification, media, or product code.
- Every optional value is omitted or `null`; clients hide its section/row. They never render `null`, `undefined`, `N/A`, `-`, or empty labels.

## Cursor pagination and product query contract

`GET /api/v1/public/products` and `GET /products/{slug}/related` use an opaque cursor. The client must treat it as an uninterpreted token and send it back unchanged.

- Default `limit` is 20; maximum is 50. An invalid, expired, altered, or sort/filter-mismatched cursor returns `400 INVALID_CURSOR`.
- The server binds the cursor to the normalized query/filter/sort snapshot and stable product identity tiebreaker. It returns `meta.next_cursor: null` when no further public result exists. This prevents duplicate/omitted records within the accepted snapshot.
- Product query parameters: `q`, `domain`, `category`, `power_source`, repeated `feature`, one or more registered `spec.<code>`, `sort`, `cursor`, and `limit`. All filters are additive AND conditions; repeated feature values are OR within that feature dimension.
- Search trims leading/trailing whitespace; compares case-insensitively and Vietnamese-diacritic-insensitively; ranks exact normalized model or approved item code before fuzzy name/category/tag/use-case matches. A server may index a real barcode for matching, but barcode is not synthesized or returned by this public DTO.
- `spec.<code>` is accepted only for a registered, currently filterable public spec code. Unknown codes or values return `INVALID_FILTER`; arbitrary field/column queries are forbidden.

## Error matrix

| `error_code` | HTTP | Used by | Safe client behavior |
| --- | --- | --- | --- |
| `VALIDATION_ERROR` | 400 | Quote input | Render `errors[field]` under the relevant field. |
| `INVALID_CURSOR` | 400 | Lists/related | Reset pagination safely and refetch the first page. |
| `INVALID_FILTER` | 400 | Products/facets | Clear the invalid selection and show a safe filter message. |
| `PRODUCT_NOT_FOUND` | 404 | Detail/related | Show Product Unavailable; do not disclose whether record is unpublished or missing. |
| `PRODUCT_NOT_AVAILABLE` | 409 | Quote/pre-order | Keep form context, explain availability changed, offer related/contact actions. |
| `IDEMPOTENCY_CONFLICT` | 409 | Quote | Same key with a different normalized payload; do not submit again under that key. |
| `RATE_LIMITED` | 429 | Any endpoint | Respect `meta.retry_after_seconds`; do not busy-loop retry. |
| `MAINTENANCE` | 503 | Any endpoint | Show maintenance state and safe estimate when supplied. |
| `UPSTREAM_UNAVAILABLE` | 503 | Read/config/quote persistence dependency | Show retry/no-network-safe state. A quote is never reported as accepted unless minimal persistence succeeded. |
| `INTERNAL_ERROR` | 500 | Any endpoint | Generic safe error, retry affordance, no stack/error body. |

## Quote request contract and idempotency

### Persisted quote schema — exhaustive

The minimal quote storage record has **exactly** these columns. Constraints are part of the contract.

| Column | Constraint / purpose |
| --- | --- |
| `id` | Internal primary key |
| `request_id` | Unique public request identifier |
| `idempotency_key` | Unique non-secret client submission key |
| `product_id` | Required public product context at submission time |
| `variant_id` | Nullable public variant context |
| `full_name` | Required PII; normalized/trimmed after validation |
| `phone_normalized` | Required PII; normalized to E.164 after validation |
| `province_code` | Nullable controlled code |
| `note` | Nullable PII/free text; sanitized and at most 500 characters |
| `consent_at` | Required server timestamp, derived only after `consent: true` validates |
| `privacy_version` | Required version presented to the user |
| `source` | Required server-derived constant `ZALO_MINI_APP` |
| `created_at` | Required UTC audit timestamp |
| `updated_at` | Required UTC audit timestamp |

There is no stored `status`, CRM ID, owner, assignment, synchronization field, retry field, outbox event, queue job, notification field, analytics payload, request context, referrer, IP, or trace field. `RECEIVED` is a response acknowledgement only.

### Submission and replay behavior

- `Idempotency-Key` header is required for every POST and must be a 16–128 character opaque client-generated value. It is never logged or returned to the client in a response body.
- The API validates/normalizes the body and verifies the selected product/variant is still publicly eligible as `IN_STOCK` or `PREORDER` before atomically creating the minimal record and its idempotency fingerprint. The request body and stored schema do not add a pre-order type, sales owner, assignment, callback date, or lifecycle field.
- A first accepted submission returns `201` with `{ request_id, status: "RECEIVED" }`. A repeat using the same key and equivalent normalized body returns `200` with the same response and `meta.idempotent_replay: true`.
- The same key with a different normalized body returns `409 IDEMPOTENCY_CONFLICT`. A validation failure creates no record and reserves no key.
- The client disables double-tap while in flight. After an ambiguous timeout it retries the exact original payload with the same key. This is an API retry/replay rule only; no background retry worker is created.
- Validation: `full_name` is 2–80 trimmed characters; `phone` matches `^(?:0(?:3|5|7|8|9)\d{8}|\+84(?:3|5|7|8|9)\d{8})$`; `province_code`, if supplied, is 1–32 uppercase letters/digits/`_`/`-`; `note`, if supplied, is <=500 trimmed characters; `consent` is exactly `true`; `privacy_version` is 1–64 printable characters.
